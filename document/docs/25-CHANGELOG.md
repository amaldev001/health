|---|---|---|
| **2026-09-19** | Initial Baseline Specifications Created | Baseline specification pack established for Healthcare Appointment Management System. |
| **2026-09-19** | Applied Explicit User Decisions D1–D19 | Resolved all 12 open decisions (DEC-001 through DEC-012) per explicit user mandate. |

| **2026-09-19** | Single Deployable Containerization Model (D10) | Provider-neutral deployment model where Express serves built frontend static files. |
| **2026-09-19** | Updated Traceability Matrix & Test Case Catalog | Expanded `21-TRACEABILITY-MATRIX.md` to map all FR-* and NFR-* IDs and updated `17-TESTING-QA.md`. |
| **2026-09-20** | Implemented Strict Environment Validation & Secrets Security | Created `config/env.js` with Zod schema requiring `MONGODB_URI`, `JWT_SECRET` (min 32 chars), `FRONTEND_ORIGIN`, and `CLINIC_TIMEZONE`. Deleted un-ignored `.env` file, created root `.gitignore`, and updated `.env.example` with names only. Removed all hardcoded secret fallbacks. |
| **2026-09-20** | Hardened Database Connection & App Lifecycle | Updated `config/db.js` to fail fast without in-memory fallback in production and sanitized URI logging. Split `app.js` and `server.js` with graceful shutdown handling for `SIGTERM`/`SIGINT`. Health check `/api/health` now verifies DB connection status. |
| **2026-09-20** | Implemented Cookie JWT & Auth Security Enhancements | Transported JWT strictly in `httpOnly` cookie (`cookie-parser`), removed Bearer token support, added CSRF `verifyOrigin` middleware for unsafe HTTP methods, implemented login rate limiter (10 per 15 min per IP+email) and register limiter, constant-time password check against dummy Argon2 hash for unknown emails, pinned JWT algorithm to `HS256`, enforced password policy (10-128 chars) using Zod, removed bcryptjs completely, enforced `mustChangePassword` route guard, and added compensating cleanup for failed registration profiles. |
| **2026-09-20** | Built Appointment Service & State Machine Rules | Created `services/appointmentService.js` keeping controllers thin. Validated patient-only booking, 30-min computed duration, clinic timezone date validation (1-60 days ahead), database partial unique index double-booking rejection (409), 24h patient cancellation rule, and automatic event notifications. |
| **2026-09-20** | Applied Medical Record Access & Public Doctor Projections | Enforced 1 record per appointment (`appointmentId` unique index, 409), restricted admin from all medical record routes (403), removed attachments, enforced author-only editing, projected only public doctor fields on public endpoints, and restricted doctor patient view to clinical relationship profiles (no address). |
| **2026-09-20** | Implemented Comprehensive Zod Validation & NoSQL Injection Protection | Created centralized validator middleware in `validators/` covering request body, query params, and URL path params (ObjectId). Enforced string trimming, length bounds, email normalization, HH:mm time formatting, YYYY-MM-DD date validation, and unknown field stripping (`.strip()`). |
| **2026-09-20** | Standardized Error Handler, Request Correlation & Logging | Rewrote `middleware/errorHandler.js` using `AppError` class. Mapped Mongoose ValidationError (400), CastError (400), Mongo 11000 duplicate key (409 CONFLICT), and JWT errors (401). Eliminated status code precedence bug and raw driver error leaks. Added `requestLogger.js` to assign `requestId` and log method, path, status, and duration ONLY without sensitive body/token data. |
| **2026-09-20** | Added Database Doctor Search & Specialization Collation Index | Created regex-escaped DB search pipeline in `utils/searchUtil.js` across doctor name, specialization name, and qualification. Added collation strength 2 index on `Specialization.name` for case-insensitive unique name enforcement. |
| **2026-09-20** | Standardized Collection Pagination & Lookup Indexes | Added standard pagination wrapper (`page`, `limit`, `total`, `totalPages`) across all list endpoints (`/doctors`, `/patients`, `/appointments`, `/medical-records`, `/notifications`, `/admin/users`). Added indexes to `Doctor`, `Patient`, `Appointment`, `MedicalRecord`, and `Specialization` schemas. |
| **2026-09-20** | Added New Endpoints & Admin Deactivation Protection | Implemented `GET /config`, `GET /patients` (admin search + pagination), `GET /doctors/:id/patients` (doctor only), `GET /medical-records` (paginated, admin 403), `PATCH /admin/users/:id/status` (prevents self/last-admin deactivation and syncs doctor profile status), `GET /doctors?includeInactive=true` (admin only), and `GET /appointments` filters (`status`, `from`, `to`). |
| **2026-09-20** | Hardened Doctor Availability & Admin Dashboard Metrics | Validated doctor schedules (max 3 windows/day, 30-min alignment, no overlaps, doctor own edit only D14). Slot generation and past slot logic operate in `CLINIC_TIMEZONE`. Added `no_show` and `today's appointments` counts to admin dashboard, running all count queries in parallel via `Promise.all`. Added pagination and `unreadCount` to `/notifications`. |
| **2026-09-20** | Completed Production Readiness Sprint | Added backend test suite (Jest + Supertest with mongodb-memory-server, 55/55 passing), frontend test suite (Vitest + Testing Library, 11/11 passing), ESLint + Prettier configuration across server/client, GitHub Actions CI workflow (.github/workflows/ci.yml), multi-stage Dockerfile & docker-compose.yml, SPA fallback serving in app.js, root README.md, E2E QA checklist in 17-TESTING-QA.md, and production deployment guide in 18-DEPLOYMENT.md. |
